# Roadmap

Known gaps and planned improvements. File an issue if you'd like to pick one up.

## Reliability

- **Stronger first-party workload health checks.** `api`, `webui`, and `logd` have no readiness/liveness probes. `core` and the scanners have readiness only. For ALB ingress, also add explicit per-service health check annotations so target health reflects real service readiness.
- **Chart standalone render/lint.** `templates/license.yaml` references `.Values.license.existingConfigMap` but `license:` is missing from `values.yaml`. Terraform masks this by always setting `license.existingConfigMap`, but `helm template fortiaigate/` fails outside Terraform.
- **Edge cases in chart templates.**
  - Setting `fortiaigate.env.csrfSecretKey` renders invalid env YAML (`value` ends up nested under `valueFrom`).
  - Unset `scanners.env.maxRpcConcurrency` renders `value:` as null.

## Architecture

- **Revisit shared EFS persistence layout.** One RWX EFS PVC currently backs app data, PostgreSQL, and Redis. For production, consider Amazon RDS / ElastiCache, or at minimum separate PVCs per workload for better isolation and performance.

## Security defaults

- **Restrict EKS public endpoint.** `cluster_endpoint_public_access = true` is enabled without `cluster_endpoint_public_access_cidrs`. Default to private endpoint access or require a CIDR list at apply time.
- **Multi-AZ NAT.** `single_nat_gateway = true` is cheaper but introduces an AZ-level single point of failure.
- **Production TLS story.** Replace the self-signed cert generated by `tls.tf` with ACM (for ALB) or cert-manager (for nginx/traefik).

## Lifecycle

- **Bump EKS default Kubernetes version.** `1.31` is in EKS extended support as of 2026-04-28 and reaches end of extended support on 2026-11-26. Move the default forward before then.

## Done
